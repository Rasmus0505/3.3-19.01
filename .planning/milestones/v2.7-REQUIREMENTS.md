# Requirements Archive: v2.7 阅读板块重写增强

**Archived:** 2026-04-06
**Status:** ✅ SHIPPED

## v1 Requirements

### Rewrite Persistence (持久化)

- [x] **RP-01**: User can unlock AI rewrite and the result is saved to IndexedDB (original text + rewritten text + mappings + articleId)
- [x] **RP-02**: When reopening a previously-read article, the saved rewrite is automatically loaded and displayed without re-calling the API
- [x] **RP-03**: User can toggle between "original text" and "rewritten text" views at any time; toggle state persists per article
- [x] **RP-04**: Rewrite history list shows which articles have been rewritten (visual indicator) and allows clearing saved rewrites

**Outcome:** ✅ All 4 requirements complete — IndexedDB persistence layer implemented, auto-load verified, toggle persistence working, history indicators in place.

### Rewrite UI Enhancement (重写UI)

- [x] **UI-01**: Rewritten words/phrases display with a yellow background highlight block (oklch-based, distinct from CEFR underlines)
- [x] **UI-02**: Hovering over a yellow highlighted word shows a tooltip with the original word/phrase
- [x] **UI-03**: The original CEFR underlines (i+1 green, above-i+1 red) are no longer applied to words that have been rewritten — the yellow block takes visual priority
- [x] **UI-04**: The yellow highlight is visually consistent between desktop and web surfaces
- [x] **UI-05**: In "original text" view, CEFR underlines continue to display as before (no regression)

**Outcome:** ✅ All 5 requirements complete — Yellow block CSS implemented (`oklch(0.93 0.16 85)`), tooltip at 200ms transition, CEFR suppression verified in ArticleWord component, cross-platform consistency confirmed, original view CEFR underlines preserved.

### Prompt Optimization (提示词优化)

- [x] **PO-01**: The rewrite prompt is redesigned with sentence-level analysis + structured JSON output (simplified word list + sentence context + original-to-simplified mappings), reducing descriptive text in the output
- [x] **PO-02**: The prompt instructs the model to preserve original sentence structure as much as possible (only replace vocabulary, minimize sentence restructuring) to reduce token churn
- [x] **PO-03**: Rewrite API call cost (estimated tokens) is displayed to the user before confirming rewrite
- [ ] **PO-04**: The new prompt is tested with at least 3 sample texts of varying difficulty and lengths to verify quality and token savings

**Outcome:** ⚠️ 3/4 requirements complete — `/api/llm/simplify-words` endpoint deployed with JSON array output, sentence structure preservation in prompt, token estimation API (`/api/llm/estimate-tokens`) and `RewriteEstimateBanner` component created. PO-04 requires human testing with real API calls (deferred).

## v2 Requirements

### Advanced Rewrite Features

- [ ] **RW-01**: User can select a rewrite difficulty level (e.g., "slightly easier" vs. "much easier") similar to Rewordify's 6-level system, using CEFR as the scale
- [ ] **RW-02**: Vocabulary column panel showing all simplified words with original↔rewritten pairs alongside the text
- [ ] **RW-03**: Side-by-side original/rewritten two-column display mode

**Outcome:** Not addressed in v2.7 — future milestone scope.

## Out of Scope

| Feature | Reason | Validated |
|---------|--------|-----------|
| Server-side rewrite storage | Conflicts with local-first constraint; IndexedDB is sufficient | ✅ |
| Batch rewrite multiple articles | Per-article rewrite is the current model; batch is future scope | ✅ |
| Rewrite with user-provided API key | Platform manages keys to keep experience simple | ✅ |
| Full Rewordify emulation (50k-word dictionary) | CEFR vocabulary table + AI covers the same need more precisely | ✅ |
