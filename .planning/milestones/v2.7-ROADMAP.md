# Milestone v2.7: 阅读板块重写增强

**Status:** ✅ SHIPPED 2026-04-06
**Phases:** 32-34
**Total Plans:** 3 plans (2 plans in Phase 33, 1 plan in Phase 34)

## Overview

v2.7 专注阅读板块重写功能的三个维度：持久化保存、AI词汇简化UI、提示词优化。实现了IndexedDB重写持久化、黄色色块高亮、Token估算等核心功能。

## Phases

### Phase 32: Rewrite Persistence

**Goal:** Rewrite results persist in IndexedDB with auto-load and per-article toggle; history list shows rewrite status
**Depends on:** None (first phase of v2.7)
**Plans:** 0 plans (direct implementation, no separate plan file)

**Success Criteria:**
1. User can unlock a rewrite and the result is saved to IndexedDB `reading_rewrites` store
2. When reopening a previously-read article, saved rewrite loads automatically
3. User can toggle between original/rewritten views with per-article persistence
4. History list displays visual indicator on articles with saved rewrites

**Status:** ✅ Complete (2026-04-06)

---

### Phase 33: Rewrite UI Enhancement

**Goal:** Rewritten words display with yellow highlight blocks; CEFR underlines give way to the highlight; original view shows CEFR underlines without regression
**Depends on:** Phase 32
**Plans:** 2 plans

Plans:

- [x] 33-01: CSS — Yellow Block Highlight + Tooltip Timing
- [x] 33-02: Verify — ArticleWord Class Logic (CEFR Suppression + Tooltip)

**Success Criteria:**
1. Rewritten words/phrases wrapped in yellow background blocks
2. Hovering over yellow highlight shows tooltip with original word (within 200ms)
3. Rewritten words no longer show CEFR underlines (yellow block takes priority)
4. Yellow highlight consistent between desktop and web
5. Original view continues to show CEFR underlines

**Status:** ✅ Complete (2026-04-06)

**Key Decisions:**
- Yellow block: `oklch(0.93 0.16 85)`, padding 4px/8px, border-radius 4px
- Tooltip transition: 200ms
- Selection overlay: blue inner border `oklch(0.65 0.18 175)`

---

### Phase 34: Prompt Optimization

**Goal:** Rewrite prompt redesigned to return simplified words only (per-order array); token cost displayed before rewrite; quality verified
**Depends on:** None (backend-only phase)
**Plans:** 1 plan

Plans:

- [x] 34-01: 新 /simplify-words endpoint + Token 估算 API + 前端集成

**Success Criteria:**
1. New rewrite prompt returns JSON array of simplified words (one per input, same order)
2. Model preserves original sentence structure (vocabulary replacement only)
3. Token cost displayed before rewrite confirmation
4. New prompt tested with 3+ texts; results show 20%+ token savings

**Status:** ✅ Complete (2026-04-06)

**Key Design Decisions:**
- Per-order array schema (方案 B): `words[i]` → `simplified_words[i]` by position
- Local replacement: Simplified words applied client-side
- Token estimation before rewrite (char/4 heuristic)
- Backward compatible: Existing `POST /api/llm/rewrite-text` preserved
