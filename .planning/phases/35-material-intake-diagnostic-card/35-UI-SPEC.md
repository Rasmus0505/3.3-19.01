## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, badge insets, inline metric separators [default] |
| sm | 8px | Chip spacing, compact card padding, label-to-value gaps [default] |
| md | 16px | Standard card padding, section spacing, history item padding [existing rhythm] |
| lg | 24px | Left/right column inner padding, stacked panel spacing [existing reading layout] |
| xl | 32px | Major card clusters and desktop breathing room [default] |
| 2xl | 48px | Sticky CTA footer padding and major dashboard breaks [default] |
| 3xl | 64px | Top-level page separation when the diagnostic stage stands alone [default] |

Exceptions: 44px minimum tap target for icon-only controls and collapsed rails; 300px minimum desktop dashboard column; 420px preferred desktop dashboard width on xl screens.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `oklch(1 0 0)` | App background, left preview surface, main dashboard canvas |
| Secondary (30%) | `oklch(0.97 0 0)` | History rail, secondary cards, diagnostic panel background, chip beds |
| Accent (10%) | `oklch(0.58 0.15 158)` | Primary CTA, selected target-level chip, recommended badge, resume status pill, active draft border |
| Destructive | `oklch(0.577 0.245 27.325)` | Delete and clear-history confirmations only |

Accent reserved for: primary CTA, selected target-level chip, recommended target badge, resume badge, retry/continue emphasis. Never use accent for body copy, neutral surfaces, or every interactive element.

Diagnostic semantics reuse the existing reading colors: preserved i+1 metrics use `oklch(0.75 0.16 175)`, above-i+1 metrics use `oklch(0.58 0.24 25)`, and neutral/meta labels use `oklch(0.556 0 0)`.

## Layout Contract

- Diagnostic is a full-page stage inside `ReadingPage`, not a modal, drawer, or inline warning card.
- Desktop at `>=900px` uses a two-column layout: left `minmax(0, 1.15fr)` original preview, right `420px` diagnostic dashboard. The right column stays sticky while the left preview scrolls independently.
- Mobile at `<900px` stacks the diagnostic dashboard first and the original preview second so the user sees the verdict, target selector, and CTA before reading the full article.
- The top history rail stays visible above the diagnostic stage. Any diagnosed-but-not-generated item must reopen directly into this stage and show a resume status badge.
- Right-column section order is fixed: stage header, difficulty triad, target-level selector, impact scoreboard, cost/time estimate, sticky CTA footer.
- Left preview is read-only original text. During Phase 35 it does not expose rewrite toggle, word selection, translation, or wordbook actions.

---

## Visual Direction

- The right column should feel like a competition diagnostic dashboard, not a plain settings sidebar: use bordered metric cards, high-contrast numerals, crisp separators, and one strong action lane.
- Make the first viewport legible without scrolling: material difficulty, user level, recommended target, preserved i+1 count, above-i+1 count, and generation estimate must all fit above the fold on desktop.
- Use charts as analytical aids, not decoration. One segmented bar or compact meter group is enough; all critical numbers must remain visible without hover.
- Keep the left preview calmer than the dashboard. The visual hierarchy should make the diagnostic panel the decision surface and the article pane the evidence surface.

---

## Component Inventory

- `History diagnostic pill`: preview title, last-opened time, status badge (`待生成` or `继续生成`), target-level badge when available.
- `Difficulty triad`: three equal-height cards for `材料难度`, `当前等级`, and `建议目标`; each card shows one large value plus one short explanatory line.
- `Target level selector`: single-select segmented chips from `A1` through `C2`; the recommended level gets a `推荐` badge but remains fully overrideable.
- `Impact scoreboard`: one compact chart or meter block showing preserved i+1 count, above-i+1 count, and estimated simplification impact. Numbers must be visible without interaction.
- `Estimate module`: one compact card that pairs expected time with expected cost; the estimate sits immediately above the primary CTA.
- `CTA footer`: primary `继续生成`, secondary `重新输入`; keep this footer visible at the bottom of the dashboard on both desktop and mobile.

---

## Interaction Contract

- Submitting material performs diagnosis only. It must never auto-trigger rewrite or generation.
- The initial submit transition goes `input -> diagnosing -> diagnostic stage`. Use a dashboard skeleton or progress shell with the copy `正在诊断材料…` until difficulty, counts, and estimate are ready.
- Target-level changes update the recommendation display, impact summary, and persisted draft state immediately. Do not add a separate `应用` button.
- The selector allows full-range override from `A1` to `C2`, even when the recommendation is far away from the current user level.
- When a draft already has a diagnostic snapshot, reopening from history lands directly in the diagnostic stage instead of returning to the textarea.
- If diagnosis fails, keep the preview visible, preserve the chosen target level, and show a secondary retry action labeled `重新诊断`.
- The main CTA label is always `继续生成` once a diagnostic snapshot exists, including history resumes.
- Persist the diagnostic summary with the draft session: source text, detected difficulty, recommended level, selected target level, preserved i+1 count, above-i+1 count, estimate, and last diagnosed timestamp.
