## Surface Contract

### Pipeline Stage View

- Use a dedicated stage surface, not the normal reading layout with a loading overlay.
- Desktop layout is `left stage rail + right stage card`; mobile collapses to `top horizontal rail + stacked stage card`.
- Stage rail must show exactly five named stages in this order: `parsing`, `difficulty judgment`, `simplification planning`, `text rewriting`, `reading-pack assembly`.
- Each stage row exposes one of four statuses only: `pending`, `running`, `completed`, `failed`.
- The running stage uses the accent color, a visible progress bar, and a one-sentence “current work” description.
- The last completed stage stays visible with a concise completion summary instead of disappearing.
- The next stage is previewed in muted styling so the user can see what the system will do next.
- Do not use a generic spinner as the main focus; the main focus is stage progression and asset assembly.

### Recovery And Failure

- On reopen with an in-progress run, restore the stage surface to the last persisted stage and stop there by default.
- Recovery must show a resume banner above the stage card: `已恢复到上次进度` plus the last completed stage name.
- The resume CTA is `继续生成`; the secondary fallback CTA is `查看原文`.
- Failure state sits inside the stage card, names the failed stage explicitly, and keeps previous completed stages visually intact.
- Original reading remains reachable after failure; do not blank the page or force the user back to input mode.

### Reading Pack Asset Page

- A successful run lands on a dedicated pack page, not the generic reading workspace.
- The pack header is the first block on the page and contains: pack status badge, target level badge, last-generated timestamp, and a diagnostic summary strip.
- The diagnostic summary strip shows exactly three metrics: material difficulty, preserved i+1 count, above-i+1 count.
- The pack header should read as a persistent asset: use a card container, a status badge, and copy that names it a `阅读包`.
- Keep the result page within the existing reading feature shell; do not invent a new top-level route aesthetic.

### Pack Modes

- Mode switching uses shared `Tabs` and exactly three tabs: `原文`, `i+1`, `逐句对照`.
- `原文` and `i+1` modes reuse the existing long-form reading renderer and tooltip/highlight behavior.
- `逐句对照` is a vertical list of sentence cards, not a table and not a full-width split-screen diff.
- Each comparison card shows original sentence first in muted styling, rewritten sentence second in dominant styling, and keeps enough padding for scanning.
- Word-level hover comparison remains available in `原文` / `i+1` modes even though sentence cards exist.

## Interaction Rules

- Primary CTA labels use verb + asset language: `生成阅读包` for first run, `继续生成` for recovery.
- Only one primary action appears per state card. Secondary actions are outline or ghost buttons.
- Disable stage CTA while the pipeline is actively running; keep status visible instead of hiding controls.
- Completed runs reopen directly into the pack page with the last selected pack mode preserved.
- Do not auto-replay finished animations when reopening a completed pack.
- Stage transitions may animate with short fades or progress fills, but motion must never delay content availability.
- Mobile keeps all actions within thumb reach at the bottom of the stage card or pack header; avoid side-by-side tertiary controls on narrow screens.
