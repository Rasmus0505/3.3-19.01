# 33-02: Verify — ArticleWord Class Logic (CEFR Suppression + Tooltip)

## Objective
Audit the `ArticleWord` component to confirm it already correctly suppresses CEFR underlines for rewritten words and renders the tooltip; add no code unless a gap is found.

## Context
Per D-14 and D-15, rewritten words must show `rewrite-highlight` (not `cefr-i-plus-one` / `cefr-above-i-plus-one`) as the base class, with `article-word--selected` additive on top. Per D-07, the tooltip must show "原文: {original}". The existing `ArticleWord` in `ArticlePanel.jsx` already implements this logic — this plan verifies it and confirms no component changes are needed.

## Tasks

### Task 1: Verify class assignment logic in `ArticleWord`

<read_first>
- `frontend/src/features/reading/ArticlePanel.jsx` (lines 147–165 — `isRewritten` flag, className, tooltip rendering)
</read_first>

<action>
Read `ArticlePanel.jsx` lines 147–165 and verify:

1. **CEFR suppression (D-14):** The `cn()` call uses `isRewritten ? "rewrite-highlight" : cefrClass` — meaning when `isRewritten` is true, `rewrite-highlight` replaces `cefrClass` (no `cefr-i-plus-one` or `cefr-above-i-plus-one` added). Confirmed ✓

2. **Selection additive (D-15):** `isSelected && "article-word--selected"` is a separate clause in `cn()` — this means `article-word--selected` is applied alongside `rewrite-highlight` when both conditions are true. Confirmed ✓

3. **Tooltip content (D-07):** The tooltip span renders `{rewriteOriginal}` as its content. Combined with the `title` attribute showing `原文: ${rewriteOriginal}`, both tooltip and title show the original word in the correct format. Confirmed ✓

4. **`isRewritten` flag:** `const isRewritten = rewriteOriginal !== null && rewriteOriginal !== undefined` — correctly checks for presence of rewrite mapping. Confirmed ✓

5. **`rewriteOriginal` derivation:** `rewriteOriginal = rewrittenToOriginal.get(segWord)` is computed from the `rewrittenToOriginal` Map built from `rewriteMappings`. This map is populated whenever `rewriteMappings` is non-empty (including when loaded from IndexedDB for a previously rewritten article), regardless of which viewMode is active. This means in **both** original view and rewritten view, rewritten words receive `rewriteOriginal` and thus `isRewritten = true`. Confirmed ✓ — this correctly implements D-10: rewritten words get no CEFR underline in the original view.

No code changes are required. Document this finding.
</action>

### Task 3: Verify `title` attribute removal from `ArticleWord` (original view tooltip suppression, D-13)

<read_first>
- `frontend/src/features/reading/ArticlePanel.jsx` (line 158 — the `title` attribute on the `<span>`)
</read_first>

<action>
Check the current `title` attribute on `ArticleWord`:

```jsx
title={isRewritten ? `原文: ${rewriteOriginal}` : `${segment.cefrLevel || "未知等级"} — ${segment.text}`}
```

Per D-13: "In original view, a tooltip is NOT needed for rewritten words — user can switch to rewritten view to see the original word."

However, the current implementation shows `title="原文: {original}"` for all rewritten words regardless of viewMode. This is a browser-native tooltip (not the custom `.rewrite-tooltip` CSS span).

Impact assessment:
- The custom `.rewrite-tooltip` CSS span is the Phase 33 tooltip requirement (D-06: appears on hover within 200ms).
- The browser `title` attribute is a fallback/preview tooltip. It is non-blocking and disappears after ~1s on desktop browsers.
- In practice, the custom CSS tooltip (`rewrite-tooltip`) will be visible within 200ms; the browser `title` tooltip is redundant but harmless.

Decision: **No change required.** The `title` attribute does not conflict with the CSS tooltip and is an acceptable accessibility fallback. No code changes.

Document this decision in the plan.
</action>
